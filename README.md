# Lexi: независимый каталог на GitHub

Публичный репозиторий: [intelligentbox/lexi-catalog](https://github.com/intelligentbox/lexi-catalog).
Действующий каталог: [GitHub Pages](https://intelligentbox.github.io/lexi-catalog/), [JSON для Android](https://intelligentbox.github.io/lexi-catalog/catalog.json).

29 октября 2026 каталог опубликован и открывается без авторизации. Старое облачное расписание ChatGPT отключено, локальная задача приостановлена. APK 1.0.3 обращается к GitHub напрямую; прежние APK требуют обновления. Фактические запуски и результаты видны в [Actions](https://github.com/intelligentbox/lexi-catalog/actions/workflows/catalog.yml). Состояние расписания задаётся переменной ENABLE_UPDATES, а не наличием страницы каталога.

30 октября 2026 успешно опубликован первый независимый ежедневный выпуск: 40 слов, 4 подборки, revision 3. [Проверочный запуск пяти уровней](https://github.com/intelligentbox/lexi-catalog/actions/runs/40955646803) и [реальное пополнение](https://github.com/intelligentbox/lexi-catalog/actions/runs/40957119044) завершились успешно. ENABLE_UPDATES=true: расписание включено. Проверены 20 автоматических тестов и приём опубликованного JSON кодом Android. Обязательные тексты карточек берутся из Wiktionary; уровень и подбор значения оцениваются автоматически.

## Что уже перенесено в исходники

- `data/catalog.json`: текущий каталог. При миграции 29.10.2026 перенесены 35 слов, 3 подборки, revision 2; следующие выпуски дополняют этот снимок.
- `data/migration-baseline.json`: контрольный снимок опубликованных карточек. Сохраняет их идентификаторы, содержание и подборки при последующих выпусках.
- `data/base-words.json`: список 100 встроенных слов для исключения повторов. Личные слова и прогресс здесь отсутствуют.
- `docs/catalog.json`: готовый статический файл для Android; `docs/index.html`: страница каталога.
- `scripts/`: чтение словаря, подготовка и проверка новых карточек, сборка сайта, подготовка перехода Android.
- `.github/workflows/`: публикация GitHub Pages и обновление каталога на сервере GitHub.

## Бесплатная архитектура

Публичный репозиторий хранит карточки, историю и скрипты. GitHub Pages раздаёт JSON по HTTPS. Стандартный публичный runner `ubuntu-24.04` запускает скрипты и небольшую открытую модель Qwen3-4B через CPU-версию llama.cpp. Нет API-ключей OpenAI, ChatGPT, платных inference API, собственного сервера или зависимости от включённого ПК. Модель и runtime скачиваются только во временную файловую систему runner; веса 2,5 ГБ не входят в репозиторий и архив проекта.

При ENABLE_UPDATES=true новые слова готовятся около 09:17 по Москве: 5 слов, по одному на A2–C2; в понедельник дополнительно 25 слов, по пять на уровень. GitHub может задерживать расписание. После 60 дней без активности репозитория GitHub может отключить scheduled workflow; его можно включить заново. Нет гарантии вечной доступности бесплатного хостинга. Уже скачанные слова сохраняются офлайн.

Публичные репозитории используют бесплатные стандартные Actions runners и Pages по действующим правилам GitHub. Код намеренно не запускает workflow в приватном репозитории, не использует larger runners, Codespaces или платные модели. Карту и платёжные данные добавлять не требуется. После переименования/переноса репозитория адрес нужно обновить в APK или сохранить старый маршрут.

Официальные правила: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [расписания](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). GitHub Models не используется: сервис [закрыт с 30 июля 2026 года](https://docs.github.com/en/github-models).

## Как пополняется база

1. Планировщик проверяет, есть ли выпуск за текущую дату, с учётом старых идентификаторов. Повторный запуск не создаёт второй выпуск.
2. Берёт кандидатов из `data/candidates.json`, затем предлагает новые с помощью локальной модели. Конечным списком кандидатов пополнение не ограничено. Дубли проверяются по всем встроенным и опубликованным словам, независимо от уровня.
3. Читает настоящую английскую статью Wiktionary. Последовательные запросы с понятным User-Agent, без обхода ограничений; при 403/429/503 работа прекращается. Cambridge и Merriam-Webster не скачиваются и не используются через API.
4. Выбирает значения только при наличии обеих явно помеченных транскрипций UK/US и русского перевода в таблице переводов соответствующей части речи и этимологии. IPA и русский термин задаёт парсер, модель их не генерирует.
5. Модель получает только английские значения и пояснения к переводам, выбирает соответствующие индексы, выбирает готовые словарные определение и пример и объясняет ориентировочный уровень. Модель не может изменить определение, пример, перевод или IPA. Словарные примеры извлекаются из раздела usage examples того же значения; цитаты и неполные фразы не используются. Код вставляет выбранный русский термин из статьи. Отдельный запрос модели проверяет соответствие определения, примера и смысла перевода. Русские определения и примеры отклоняются детерминированной проверкой языка. Это автоматическая проверка той же моделью, **не независимая экспертная лингвистическая оценка**; возможны ошибки и требуется редакторский контроль.
6. Проверки схемы, источников, лицензии, примеров, повторов, объёма и полного состава всех уровней выполняются до записи. Неполный выпуск не сохраняется. Сбой источника или модели оставляет прошлый каталог.
7. GitHub сохраняет изменения отдельным коммитом и публикует Pages в том же workflow. Отдельный push-trigger для коммитов GITHUB_TOKEN не требуется. Конкурирующие запуски сериализованы; force push не используется.

Если генерация не удалась, владелец увидит failed run в Actions; уведомления настраиваются в его GitHub. Недельный выпуск, пропущенный из-за сбоя в понедельник, можно повторно подготовить в тот же день; система не обещает задним числом заполнять все пропуски. Для остановки автопополнения достаточно поменять `ENABLE_UPDATES` на `false`; чтение каталога продолжится.

## Развёртывание после подключения GitHub

1. Создать **публичный** репозиторий `lexi-catalog` с основной веткой `main`. Загрузить содержимое этого проекта в корень, включая скрытую папку `.github`. В репозиторий не должны попадать ключи подписи Android, пароли, APK, экспорты пользовательского прогресса, `.runtime` или исходники приватного сайта.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**. Settings → Actions: разрешить стандартные Actions; обновлению нужен `contents: write` из workflow. При запрете политикой организации владелец должен разрешить его; обхода прав в проекте нет.
3. Actions → **Publish and update Lexi catalog** → Run workflow → `publish`. Проверить, что `https://<владелец>.github.io/lexi-catalog/catalog.json` открывается без авторизации, в том числе на телефоне. В этом репозитории рабочий адрес уже указан в начале README; шаблон нужен при переносе к другому владельцу.
4. Запустить тот же workflow с `mode=verify`. Он скачает проверенные runtime и модель и попробует подготовить пять реальных карточек, по одной на каждый уровень, не добавляя их в каталог. Прочитать карточки в журнале и убедиться в качестве и времени выполнения. Пока этот запуск не завершился успешно, автоматическая генерация не считается проверенной.
5. Создать repository variable **ENABLE_UPDATES=true** в Settings → Secrets and variables → Actions → Variables. Секретов не требуется. Выполнить ручной `update`, когда по плану отсутствует выпуск; проверить новый JSON и загрузку в приложение. Можно повторить вручную при задержке расписания.
6. Подготовить обновление Android с фактическим адресом, сохранить прежний пакет и ключ подписи, увеличить versionCode. Существующий каталог должен быть заново сверен с прежним сервером непосредственно перед переходом: к этому моменту он может пополниться. Сначала перенести добавившиеся карточки и повысить revision при необходимости.
7. Проверить обновление поверх установленного APK, сохранение прогресса, новые слова и офлайн-режим. После этого отключить старое облачное расписание и организовать переход для прежних версий приложения. Пока старые APK не обновлены, им нужен старый адрес или совместимый прокси. Новое приложение после переключения обращается только к GitHub.

## Подготовка Android

`scripts/migrate_android.py` получает реальный публичный URL GitHub Pages, проверяет JSON и сохранность снимка, затем создаёт **отдельную копию** Android-исходников с новым адресом и привязкой ETag к источнику. При недоступном каталоге или фиктивном URL код не переносится.

```powershell
python scripts/migrate_android.py --source C:/path/to/lexi-android --destination C:/path/to/lexi-android-github --catalog-url https://OWNER.github.io/lexi-catalog/catalog.json
```

Это подготовка исходников, не сборка APK. После неё нужно обновить версии, документацию и проверки снимка; собрать APK прежним приватным ключом. Ключ никогда не помещается в публичный репозиторий. Путь с OWNER выше — шаблон, его нельзя оставлять в приложении.

## Проверки локально

Python 3.12+, Node.js нужен только для дополнительной проверки совместимости с исходниками Android.

```text
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/build.py
python scripts/update.py --plan
```

Проверены перенос, повторы, неизменность опубликованных карточек, баланс уровней, даты, повторный запуск, источники, IPA, разделение языков/этимологий, отказ модели/сети, сборка ежедневного и недельного выпусков с моделью-заглушкой. Парсер также проверен на реальных статьях; слова без подтверждённых UK/US IPA и русского словарного перевода пропускаются. Workflow проходит actionlint. Проверены SHA256 и наличие `llama-server` в официальном Linux-архиве. Публикация Pages проверена на GitHub. Полный запуск Qwen выполняется в режиме verify; перед включением расписания нужно прочитать пять полученных карточек в журнале, а не ориентироваться только на зелёный статус задания. Предыдущая версия генератора, создававшая русские переводы моделью, заменена после проверки качества; тестовые карточки не публиковались.
